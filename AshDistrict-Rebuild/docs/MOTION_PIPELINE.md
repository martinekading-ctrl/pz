# 人物动作基线（第一步）

目标是先把玩家行走、慢跑、起停、转向放在可重复测试的场景中校准，再把同一套控制方式接到正式地图、武器和僵尸。`scenes/motion_lab.tscn` 是独立动作测试场：WASD 移动、Shift 慢跑；地面每格 1 米，左上角显示目标速度、实际速度、动画倍率和每帧根位移。

## 素材实测

Quaternius CC0 `UAL1_Standard.glb` 中的 Walk 是原地循环，保留它作为幸存者步行动作。旧版自制两骨骼腿部轨迹虽然通过脚底数值检查，却在实际画面中出现明显的腿部扭曲，因此已从玩家走跑动作中撤除。现在跑步使用 CMU 02_03 真人慢跑动捕，只移植动作到现有的 65 骨骼成年角色；角色外观不变。截取连续完整步态，移除水平根位移，保留骨盆上下起伏，并对循环接缝做小幅平滑。来源及使用条款见 `art/characters/motion_sources/SOURCE.md`。走 / 跑每圈按约 1.2 / 2.0 米匹配当前 1.35 / 2.7 米每秒的移动速度。

测试场临时给这些原地动画的**副本**加入线性根位移轨道，由 `AnimationTree` 混合待机、走路、慢跑，再通过 `get_root_motion_position()` 驱动 `CharacterBody3D.move_and_slide()`。这条位移轨道按步幅补入，用于验证动作和碰撞体的同步；正式地图仍由现有 2D 碰撞控制移动。

## 已接入正式地图

正式地图按实际移动距离计算播放速度；移动加入加速和减速，视觉朝向跟随实际速度转弯，走跑切换沿用原来的左右脚相位，避免每次重新从第一帧起步。碰撞与战斗逻辑仍使用原来的 2D 地图坐标，以免在动作试验阶段破坏既有系统。

## 下一步验收

当前素材没有专门的走/跑起步、刹停和转身片段。正式地图也尚未由测试场的根位移控制器直接驱动。下一步应制作同一骨架的起步、停步和转身动作，继续检查脚底滑动、持枪上身混合，以及手机帧率。一次录屏只能验证这版跑步循环在指定视角下没有明显错腿，不能代表所有方向与场景已经完成视觉验收。

## 复现

运行 `godot --path . res://scenes/motion_lab.tscn` 打开动作测试场。`tools/capture_motion_sequence.gd` 和 `tools/capture_live_motion_sequence.gd` 录制待机、走路、慢跑、转向和停步过程；`tools/capture_live_motion_closeup.gd` 在正式地图中放大录制跑步，输出到 `build/live_close/` 供逐帧检查。自动验证脚本为 `tools/test_motion_lab.gd`、`tools/test_jog_clearance.gd`；正式地图的方向、帧率、加减速和碰撞验证为 `-- --player-test`，战斗回归为 `-- --combat-test`。数值和录像都不能取代玩家对动作观感的验收。
